## Standalone ADE migration

- Native Chat groups only consecutive recorded tool calls; summaries count observed calls/unique recorded targets, never successful outcomes. Recorded images use bounded exact-record same-origin serving, with no host-path or remote-URL selectors. DSH permission choices come from its mounted runtime roster and require native confirmation under the input lock. DSH rewind resolves an opaque public message/source/revision to a verified native user boundary, rejects drafts/active writers/stale sessions, confirms shutdown, then opens a receipt-fenced native continuation cut without restoring disk files or auto-submitting the returned draft. Hide actions without verified capabilities. See `docs/native-chat-features.md`.
- Codex rewind forks before an exact native user turn; Claude uses only the official SDK's bounded storage fork, never a model query. SDK code is bundled from a pinned development dependency, without its optional native CLI in the application. Antigravity/CodeBuddy use their native rewind selector inside Chat rather than guessed text-to-message matching. Compaction dividers require native boundary metadata and omit summaries; a generic clear is not compaction. Confirmed interruption labels retain measured working time.

- `providers/contextUsage.ts` and `runtime/providerContext.ts` own bounded exact-session context measurements. Never substitute cumulative spend, guessed model limits or chat-text token estimates. `ContextUsageMeter.tsx` uses the shared popover and loads native OpenCode-family/CodeBuddy capacity for the exact measured model when chat opens. CodeBuddy local-command context reports must remain session-bound and never be requested by collection. `ConversationPositionRail.tsx` navigates loaded public prompts with local pane scrolling, source reset, reduced motion and observer cleanup. See `docs/chat-context-navigation.md`.

- `runtime/dsh.ts`, `dshPlugin.ts` and `dshCatalog.ts` own DeepSeek Harness support. Launch patches observe exact root Session events and the installed TUI channel without editing user profiles. Bind workspace/session/launch token, keep public projections bounded, require native ready plus an empty composer before sending, and confirm slash controls from fresh native state. User cancellation comes from explicit turn-end cause. Same-workspace resume keeps the native ID; cross-worktree resume creates a bounded full native continuation with a fresh ID and destination header through native persistence, preserving the original. Hold the source's native writer lease while copying and never retry uncertain continuation receipts. Native setup and permissions remain in Terminal. See `docs/dsh-integration.md`.

- Desktop `phone.cjs` owns opt-in exact Tailscale HTTPS origin settings through trusted main-frame IPC. Backend `phoneOrigin.ts` validates the same restricted origin; HTTP Host/Origin and terminal origins use the live setting. Disable revokes remote streams, never agent processes or input. Keep loopback binding, no wildcard/public configuration endpoint, and no automatic Tailscale/Funnel setup. See `docs/phone-connection.md`.
- Packaged speech addon discovery derives the physical `app.asar.unpacked` dependency root from backend-owned `ADE_DIST_DIR`, never the real resources cwd or an adjacent host package. Windows packaging runs the production resolver and native addon API check in the packaged executable before publication.
- Renderer `terminalTouch.ts` owns bounded finger-to-scroll routing through xterm public APIs. Preserve native Codex alternate-screen mouse modes: fullscreen history belongs to the CLI, while normal-buffer history scrolls locally. Touch gestures never become arrow keys; retain pinch zoom, text selection and disposal cleanup.
- `terminalSurface.ts` waits for visible, stable modal geometry before xterm initialization. Measure an unpadded inner surface. `terminalViewports.ts` serializes the most recently active view's PTY grid; passive views follow server dimensions without local reflow, and disconnect restores the remaining view. Focus/visibility changes never replay input.
- Shared `Modal` owns nested body/touch scroll locking through `modalScrollLock.ts`: preserve page position, allow in-modal scroll and pinch zoom, and never let backdrop/edge gestures scroll the background. Dictation callbacks/timers are session-fenced; browser completion must not abort an already ended recognizer, and local mic/context teardown is idempotent.

- `runtime/sourceControl.ts` owns explicit user-invoked staging, unstaging, staged-only commits, origin fetch/publish/push, force-with-lease, fast-forward pull/sync, rebase and GitHub PR creation. `/source-control/` routes accept typed actions, discovered worktrees/refs and fresh repository versions; no raw commands, remote URLs or flags. Passive collection never mutates Git. `features/sourceControl/` owns the sidebar and lazy read-only Monaco diff review. Keep private/symlink exclusions, per-checkout locks, stale-state refusal and uncertain-action warnings. See `docs/source-control.md`.

- `runtime/speech.ts` owns fixed-manifest model downloads and bounded ordered local PCM sessions; `speechWorker.cjs` isolates native sherpa-onnx inference. Audio stays ephemeral, at most 60 seconds, and never becomes terminal input or automatic message submission. Browser/local engine, microphone and Toggle/Hold preferences live in `features/workflow/voicePreferences.ts`; capture uses the local AudioWorklet and stops on pane disposal. Model hashes/revisions stay backend-owned. Package the platform native addon and speech worker outside ASAR; no dependency on an installed Orca runtime.

- `runtime/organization.ts` owns Workflow / Organization execution. The message endpoint creates configured runs only when enabled and explicitly confirmed. With Workflow disabled, a launch-bound private CLI identity may explicitly begin an agent-defined team; it never changes the saved graph. Collection stays observational. Settings setup installs the bundled standalone CLI/skills from `resources/orchestration`. No Orca runtime dependency. Preserve DAG blockers, run/session/launch-token fencing, explicit worker results, one writer per checkout, uncertain-send protection, and clean integration through an owned worktree. See `docs/workflow-runtime.md`.

- `runtime/agentPreferences.ts` validates persisted default/enabled agents and fixed Manual/Auto/Yolo launch mappings. Antigravity Auto is unsupported. `runtime/interaction.ts` parses only a waiting owned terminal's current rendered numbered prompt; interaction answers are prompt-bound, one-shot and serialized with message/terminal input. Never accept executable text, infer an approval from ordinary output, or retry uncertain answers. Complex/native-only prompts remain in Terminal.
- `turn_results` persists up to 200 explicit completed/failed/interrupted turn observations for standalone Inbox. Turn completion is not task success; do not promote these Inbox entries to Kanban agent task results. `runtime/resources.ts` collects bounded cached OS process-tree working sets from owned roots and desktop metrics, without double-counting PIDs; report the smaller fallback scope explicitly if enumeration fails.

Preserve Antigravity terminal outcomes through late tool/bookkeeping hooks until a new invocation. Credentials and subprocess output remain backend-only; only allowlisted provider authorization URLs reach the browser.

## Project Scope & Conventions

- **Application Type**: Local React 19 + TypeScript frontend with a lightweight native Node HTTP backend.
- **Runtime scope**: Collection is observational. The explicit agent-message endpoint may send user-authored messages and attachments to discovered agent terminals. Never create runs or modify task status from the dashboard.
- **Contract-First Design**: The backend and frontend communicate through normative types defined in [`shared/contracts.ts`](shared/contracts.ts). Any updates to data models must originate or be mirrored in `shared/contracts.ts`.
- **Zero Raw CLI Passthrough**: The server strictly validates all CLI invocation arguments against an internal allowlist in [`server/integrations/cliValidators.ts`](server/integrations/cliValidators.ts) and [`server/integrations/cli.ts`](server/integrations/cli.ts). Never accept arbitrary command flags or user inputs as executable commands.
- **Localhost & Origin Constraints**:
  - Backend runs on `127.0.0.1:4317`.
  - Frontend development runs on `127.0.0.1:5173`.
  - CORS and origin checks permit only loopback origins (`127.0.0.1` and `localhost` on ports `4317` and `5173`). Wildcard CORS is prohibited.
- **Truthful Data & Degradation**:
  - No fabricated states, progress estimates, or synthetic orchestrators.
  - Failures in upstream dependencies (Orca CLI or `gh`) are communicated via explicit `Section<T>` envelopes containing `SourceMeta` and `Issue` structures.
  - Distinguish agent state (`working`, `waiting`, `blocked`, `completed`, `failed`, `idle`, `unknown`) from workspace status and terminal process liveness.
  - GitHub activity includes bounded commits, pull requests and repository-wide issues. Push events are excluded. Worktree scope must derive branch/path from discovered metadata, never executable user input.
  - GitHub pagination fetches 20 upstream entries per page, independently per activity. Advance issue pages using the raw upstream count before excluding PRs. Bind accumulated pages to project/repository/scope, cancel obsolete requests, deduplicate stable IDs, and preserve loaded history during first-page refreshes.
  - GitHub badges represent loaded items, with `+` while more pages are available; never imply an exact repository total. Historical pages extend notification baselines without creating unread arrivals. Loading uses shimmer skeletons with a reduced-motion fallback and explicit retry after errors.
  - GitHub account fallback is request-local through saved `gh` accounts. Never switch global active accounts or expose tokens through arguments, API responses, logs, or plaintext cache keys.
  - Conversation history contains public agent/user turns only, never tool output or internal thinking. Resolve exact provider/session provenance, bound file reads, and bind opaque cursors to project/node/run/source. Model/effort fields contain observed effective metadata only.

## HTTP Endpoints & API Contract

`server/runtime/agentHistory.ts` owns bounded, cached provider-native session discovery and public history summaries. `GET /api/agent-history` supports Workspace/Project/All scopes, bounded search and pagination, with explicit scan/read limits and project counts. Never expose transcript file selectors or accept provider UUIDs/commands from the browser. `POST /api/projects/:projectId/resume-history` accepts only an opaque indexed sessionId and discovered worktreeId, revalidates provider metadata and resumes once in the selected worktree. `sessions.resumeHistory` refuses a session running elsewhere, reopens closed entries, moves registry ownership without moving files, and preserves observed `sourceCwd` for exact transcript/Codex binding checks. Ordinary node resume keeps its existing-worktree requirement. `src/features/agents/` owns the right sidebar history UI and the typed session drag payload; worktree drops display Move here and use this same fenced endpoint.

Standalone ADE supports `DELETE /api/projects/:projectId` to remove registry metadata only. It rejects projects with open agent tabs and preserves all project files and worktrees.

Standalone `POST /api/projects/:projectId/nodes/:nodeId/resume` accepts an empty JSON object only. Agent resume is limited to saved provider UUIDs and the exact discovered worktree; an owned shell can instead reopen its fixed detected shell in that worktree without replaying commands. `server/runtime/codexThread.ts` owns bounded fixed-method Codex app-server binding; `agyBinding.ts` captures authenticated, workspace-checked Antigravity `conversationId` hook metadata. Claude uses an assigned `--session-id` and exact `--resume`. Never infer a thread from terminal text or the latest global history. Native Chat remains unsupported.

`server/http/terminalSocket.ts` owns `/api/projects/:projectId/nodes/:nodeId/terminal-stream` upgrades, loopback origin checks, fixed input/resize messages, bounded output and renderer acknowledgement credit. Shared wire types live in `shared/contracts.ts`. Initial terminal streams restore a bounded host-sized screen checkpoint from `runtime/terminalScreen.ts`, then continue at its exact parsed-output cursor. Keep input ordered, never replay uncertain writes, and stop upgraded sockets during runtime shutdown. Secure local development permits `https://127.0.0.1:5173` and `https://localhost:5173` socket origins alongside the documented HTTP origins.


- `GET /api/inbox` returns `Section<InboxData>` with up to 200 observed agent/task results across projects. Collection is cached for 30 seconds, shares in-flight reads, and checks at most 10 recent runs with two run jobs in flight. Never infer failure from message text, tool errors, or liveness. Attribute task results to their worker's discovered workspace. Inbox, GitHub and local-commit handled/unread state persists through the bounded backend notification-state API, so every browser and device shares it; the 24-hour project failure edge uses the latest result per agent/run and excludes handled items.
- Node details support `direction=older` for bounded backward transcript pagination. Bind cursor direction as well as project/node/run/source, and include direction in cache keys. The agent modal opens at the newest end, prepends 20 older public turns on top-scroll or **Load more**, preserves the scroll anchor, and cancels obsolete requests. Never treat a forward cursor as older history.
- `GET /api/projects/:projectId/nodes/:nodeId/events` streams `conversation` events containing `Section<ConversationPage>` forward deltas, with optional runId and opaque forward cursor. Reads are bounded to 20 public turns every 2 seconds, non-overlapping, with 15-second heartbeats and at most 32 connections. Preserve the forward cursor on reconnect and page hiding; keep older-history cursors separate. Close streams on selection changes and modal dismissal. Stream resets reload the exact source instead of merging sessions.

## Error Responses

All error payloads conform to `ApiError` from [`shared/contracts.ts`](shared/contracts.ts):

```json
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "Query parameter limit must be an integer between 1 and 200",
    "retryable": false
  },
  "requestId": "uuid"
}
```

Standard error codes:
`INVALID_ARGUMENT` (400), `FORBIDDEN_ORIGIN` (403), `PROJECT_NOT_FOUND` / `RUN_NOT_FOUND` / `NODE_NOT_FOUND` (404), `METHOD_NOT_ALLOWED` (405), `RATE_LIMITED` (429), `CLI_MISSING` / `CLI_TIMEOUT` / `CLI_FAILED` / `INVALID_UPSTREAM` / `INTERNAL` (500).

## Development Conventions for Agents

1. **Git scope**: Do not push, create remote branches, or perform PR actions during development unless the user explicitly requests those actions. The Source Control feature may perform its fixed typed Git/PR actions only in response to an explicit user action; passive runtime collection must never mutate Git or publish anything.
2. **Observe Concurrency Boundaries**:
   - Backend files: [`server/`](server/), [`shared/contracts.ts`](shared/contracts.ts), [`scripts/`](scripts/).
   - Frontend files: [`src/`](src/), [`index.html`](index.html).
   - Documentation files: [`README.md`](README.md), [`AGENTS.md`](AGENTS.md).
   - Shared coordination files: [`.orca/runs/live-dashboard/`](.orca/runs/live-dashboard/).
3. **Preserve Ongoing Work**: Respect concurrent worker edits and review findings tracked in `.orca/runs/live-dashboard/review-findings.json`.
4. **Lifecycle Communication**: Give concise progress updates. Check an Orca mailbox only when working in an explicitly assigned orchestration task.
