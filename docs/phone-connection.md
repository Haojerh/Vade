# Connect a phone through Tailscale

In the desktop app, open **Settings → Connect phone**. Sign in to Tailscale on both devices. **Set up connection** opens an owned embedded shell and stages the fixed `tailscale serve --bg http://127.0.0.1:4317` command once. Press Enter to run it and complete native Tailscale prompts. **Check connection** performs a bounded fixed `tailscale serve status --json` read and fills in a unique private root proxy address pointing at Vade; public Funnel mappings, other services and ambiguous results are not selected. You can also paste the HTTPS address manually. Enable access, then open the saved link in the phone browser. No app restart is required. The laptop must stay awake with Vade running. This is the same live workspace, including agent input and file operations; Tailscale access rules control who can reach it. Keep Funnel disabled. The app does not install Tailscale or submit the staged command automatically.

Setup uses a separate `WorkflowSetup` instance in the phone-connection data directory, sharing the installation shell/readiness/staging implementation without sharing its sessions or database. Only trusted desktop IPC opens or closes it. Its socket route requires the local desktop origin and exact owned IDs. Closing the settings screen closes the setup shell; background Serve remains under Tailscale's ownership. Setup never touches project agents or worktrees.

The desktop main process validates a single HTTPS `device.tailnet.ts.net` origin and persists it in its user-data directory. Only the trusted local desktop main frame can read or change this configuration through fixed preload IPC. The backend still binds to loopback. Startup receives the saved setting; subsequent changes use utility-process messages with an acknowledgement timeout, never a public configuration endpoint.

HTTP host and Origin checks cover static modules, API requests and streams; terminal WebSocket origins use the same exact address. A wildcard, arbitrary website, IP, credentials, nonstandard port, path, query or fragment is refused. Disabling access revokes new remote requests and closes active remote HTTP streams and terminal sockets without stopping agents. Existing in-flight actions may finish; revocation never replays or cancels terminal input. If acknowledgement fails, the UI reports the uncertainty and a restart applies the persisted choice.

This resolves the blank page caused by module-script Origin headers being rejected by the previous localhost-only allowlist. No remote connection is enabled by default. Native desktop-only features (folder picker, updater and connection settings) remain unavailable in the phone browser.

Setup includes official Tailscale download and installation links. Remote connection failures tell the phone user to check the laptop app, its saved access setting and both Tailscale connections; source-build commands and Git installation stay in local-computer instructions. Disable access uses the shared danger confirmation dialog before revocation.

The terminal renderer handles one-finger vertical drags through xterm's public scroll API. Fullscreen alternate-buffer TUIs with active mouse reporting receive bounded native wheel reports instead; gestures never become arrow-key input. Codex's observed alternate-screen and mouse modes are retained, so both touch and mouse wheels scroll its native transcript instead of an empty local alternate buffer. Shift-drag retains xterm selection when native mouse tracking is active. Pinch zoom, horizontal gestures and existing text selections remain available. Touch listeners are removed with the pane. Automated gesture tests cover routing and cleanup; real phone hardware remains necessary to verify browser-specific touch and keyboard behavior.

Every attached terminal view proposes its available grid; the most recently focused, resized or interacted-with view controls the single PTY grid. Passive views render that observed grid without resizing it on each output packet. Disconnecting the controlling view restores the last-used remaining view's size. The socket server serializes resize changes and publishes size-only updates. Renderers keep that observed grid when applying cursor-addressed output rather than locally reflowing a fullscreen UI. Touch-capable devices use xterm's DOM renderer; desktops retain WebGL where available. Padding wraps a separate unpadded measurement surface, so FitAddon cannot allocate rows inside the padding. Initial xterm creation waits until its dialog is visible, entry motion finishes and fonts are ready; closing during this wait cancels initialization.
