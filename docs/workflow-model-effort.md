# Workflow model and effort selection

The workflow editor uses the same bounded native catalog reader as live Chat for OpenCode, OpenCode 2 and Kilo. Each model retains its own advertised variants; models without variants have no separate effort control. OpenCode 2 uses its native model API rather than parsing the v1 CLI output.

These TUIs do not advertise a top-level `--effort` flag. On an explicitly configured new workflow launch, Vade waits up to 20 seconds for the owned empty prompt, then uses the existing idle-process-fenced `/variants` picker and its current-selection acknowledgement. Concurrent input, a replaced process, a setup prompt or an uncertain operation stops initialization. Vade does not retry the command, submit a task after a failed initialization, or replay the setting on session resume. The terminal remains available for inspection.

CodeBuddy's workflow catalog uses a fixed metadata-only ACP exchange: initialize, then create an in-memory session in a private temporary directory. The process uses `--no-session-persistence`, disabled hooks, user-only settings, an empty strict MCP configuration and noninteractive permissions. No prompt, file/tool request, authentication or setting change is sent. Vade rejects provider requests for client tools, caps output at 2 MiB and total execution at 25 seconds, closes the process and removes its temporary directory. Only native model IDs and allowlisted values in each model's `_meta.effortOptions` reach the renderer. Missing capabilities stay empty; failure is explicit. Exact model IDs remain visible to distinguish duplicate native display names. Live Chat continues using its owned session's native effort panel. The separate `ultracode` dynamic-workflow mode is not inferred from ordinary model effort metadata.

Read-only inspection on 2026-10-26 confirmed the installed CodeBuddy 2.173.0 native `toAcpModelInfo` function (character 6,428,396) returns model-specific effort options; `modelEffortOptions` (6,428,060) uses the native capability resolver. Its `dist/codebuddy.js` SHA-256 is `2af9a6c9cf7c9053c4a0e0a5d3e7df9d4b2428bbd51c013d8aebe71e654fcf49`, matching the artifact documented in [CodeBuddy controls](codebuddy-chat-controls.md). A metadata-only ACP probe returned low/high/max for both distinct DeepSeek Flash IDs, high for hy4-preview, and low/high for hy3. No inference or running-agent settings change was performed. A whole-bundle REA analysis timed out; bounded static inspection and this protocol observation establish only the described catalog behavior.

The editor supports dragging Out to In with a line preview and valid-target highlights, or clicking Out then a target card. Escape/Cancel exits connection mode. The selected node's Wait for checkboxes provide the same dependency editing without drawing lines. Arrange lays out dependency stages from left to right and preserves graph topology and configured agent settings.

Multiple incoming graph edges are supported. A review node with both Frontend and Backend as predecessors is eligible only after both report explicit completed task results. Nodes without predecessors implicitly connect to the orchestrator. Eligibility does not dispatch a node by itself: the orchestrator dispatches it through the CLI. Shared-checkout workers remain serialized; isolated workstreams retain their integration gates.
