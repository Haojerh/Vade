# Chat context and message navigation

The Chat composer has a context ring once a native usage reading exists; no icon is shown while usage is unknown. Hover with a mouse or click/tap it to open the shared animated popover. Context metadata loads with the chat; hovering only reveals already-loaded data. The card shows the latest native context measurement, capacity and remaining tokens when available, plus recorded input, output and cache counts. The percentage is not cumulative session spend. Counts can exceed capacity; the text retains that percentage while the visual bar stops at 100%.

| Provider | Context source | Capacity |
| --- | --- | --- |
| Codex | Exact JSONL `event_msg/token_count`, `last_token_usage.total_tokens` | Native `model_context_window` |
| Claude Code | Latest root assistant input plus cache creation and cache reads | Only an explicit native capacity; no fixed model default |
| CodeBuddy | Latest root response `providerData.usage.inputTokens`; cached input is already included. Recorded native `/context` reports supply rounded occupancy when present. | Exact model's native ACP `_meta.maxInputTokens`, or an exact-session recorded `/context` capacity |
| OpenCode / OpenCode 2 / Kilo Code | Latest exact-session assistant input plus cache reads/writes in read-only SQLite | Exact measured model's native catalog `limit.context`, loaded when the chat opens or the measured model changes |
| DeepSeek Harness | Exact owned TUI channel `contextOccupancy`, labelled as a provider estimate for projected readings; falls back to `lastUsage` input plus cache reads/writes | Native occupancy/channel capacity |
| Antigravity | Latest exact conversation `gen_metadata` request context | Native `max_context_tokens`; occupancy is explicitly labelled a provider estimate |

Request counts are labelled as the last request. Output appears separately and is not added to request-input estimates. The cache rows follow native accounting: Claude, DSH and OpenCode input excludes the separate cache counts, while CodeBuddy input already includes them. Codex uses its own reported total. Native providers can change context between requests, compact history or switch models. Observed resets and model changes invalidate incompatible readings. DSH must be launched or resumed with the new observer to report context; existing older observers remain unavailable until then.

`providers/contextUsage.ts` folds bounded metadata records after exact transcript binding. `runtime/providerContext.ts` reads discovered read-only provider databases. Reads have row/byte limits, ignore child sessions, and never tokenize public chat text or search tool output for usage. Capacity discovery reuses the existing fenced chat-options catalog; it does not issue slash commands or prompts. No additional polling timer is introduced. Normal snapshot events carry context metadata.

The right-side message rail marks loaded public user turns, with the active reading position highlighted. It centers within the visible messages, excluding the composer, and tracks composer resizing. Hover/focus previews a prompt and its first public answer in a shared top-layer popover bounded to the modal; click/tap jumps within the chat pane. Arrow keys traverse prompts and Home/End choose the first/last loaded prompt. Loading older history adds its positions without changing the source or losing the scroll anchor. Long histories sample visible ticks while retaining the active and focused positions; keyboard navigation still covers every loaded prompt. The rail does not invent positions for unloaded history. Geometry observers and listeners are disposed when the chat closes; reduced motion uses immediate scrolling. Expanded inline tool details use the main pane's vertical scroll, preserving horizontal scrolling of code without trapping vertical swipes in a nested panel.

## Reference and evidence

Claude system/local-command records for `/context` contain the native rounded context estimate and advertised window. The reader accepts only the exact bound session's recorded command output, removes formatting, and projects that estimate without mixing in last-request cache rows. For the observed custom-model session this recovered `35.3k/272k`; the `[1m]` model suffix is never interpreted as capacity. Later API responses restore explicitly labelled last-request usage while retaining capacity only for the same observed response model. A changed model invalidates retained capacity. Collection does not invoke `/context`, alter statusline configuration or estimate tokens from chat text.

Hover dismissal checks both the trigger and floating card before closing, so a delayed leave event cannot dismiss a card that is still hovered or focused. Kilo catalog matching preserves the provider prefix even when a native model ID contains another slash.

REA Evidence `ev_e61201428cd73319631854693370d390d2f5551e8ad8c4d1e741319acdd03022` covers extracted installed CodeBuddy model metadata and context rendering functions (artifact SHA-256 `f2013674fd79a6c9bccb0c8ff3836784bbbd4c4ec62ba97d928b264bcf1ee002`). It confirms native `maxInputTokens` metadata and the formatted `/context` report. Vade does not adopt the native formatter's fallback capacity. Reports are accepted only from bounded native local-command records in the bound session, never ordinary chat text; model changes invalidate retained report capacity. Static evidence and fixture tests establish these formats, without sending a live provider request.

The design and accounting were compared with Orca revision `dc57b3d`: [context ring](https://github.com/stablyai/orca/blob/dc57b3d/src/renderer/src/components/native-chat/NativeChatContextUsageRing.tsx), [message rail](https://github.com/stablyai/orca/blob/dc57b3d/src/renderer/src/components/native-chat/NativeChatMessageRail.tsx), [Codex accounting](https://github.com/stablyai/orca/blob/dc57b3d/src/main/codex/codex-context-usage.ts), and [Claude accounting](https://github.com/stablyai/orca/blob/dc57b3d/src/main/claude/claude-context-usage.ts). Vade uses its existing standalone metadata, bounded history and shared UI components.

Antigravity descriptor inspection used shipped `agy.exe` SHA-256 `074c7b99b7727dcd2c7437973454d0856181a1006c97a4fad91a1ed23c10ad44`. The bounded decoder follows `CortexStepGeneratorMetadata.chat_model=1`, `ChatModelMetadata.chat_start_metadata=9`, `ChatStartMetadata.context_window_metadata=10`; context fields are `estimated_tokens_used=1` and `max_context_tokens=4`. Usage fields in `ChatModelMetadata.usage=4` are input `2`, output `3`, cache write `4`, cache read `5`. REA verified the binary identity; native engine analysis was unavailable, and the descriptor mapping came from static byte inspection. Fixture tests cover the mapping, provenance rejection and invalid latest records; no live provider request was sent for verification.

Follow-up REA identity Evidence `ev_621c9d8a92818d615bfb05c1291fcb3c4df3b18013b9f319f6861d384d6f0981` confirms the same installed artifact. Read-only inspection of recent real session metadata reproduced a ten-byte int64 `-1` sentinel in `ChatStartMetadata` field 2, immediately before context field 10. The protobuf reader now skips valid wide scalar values without rounding them into numeric facts; malformed, overflowing and unterminated encodings still fail closed. The corrected reader recovered 168,961 used tokens from the observed request. Its persisted capacity was 256,000, while the user's live `/context` view advertised 1,048,576: persisted request metadata and the live command can differ. Vade labels the persisted source explicitly and does not guess the live capacity or invoke `/context` during collection.
