# Native Chat activity and actions

The native Chat view groups consecutive recorded tool calls between public messages into one expandable activity summary. Expanding keeps the existing per-call disclosures and recorded edit previews. Categories describe observed calls, not successful edits, command exits or task completion. Public messages remain separate and retain chronological ordering, pagination and source binding.

## Saved round activity

After a verified turn settlement, earlier assistant prose and recorded tool calls fold behind **Worked for …** or **Interrupted after …**. The last assistant prose stays visible; trailing tool calls do not disqualify it as the displayed answer. User prompts and compaction/checkpoint notices stay outside the fold. Active rounds remain open, and ambiguous queued-user ownership is left unfolded. Silence, process exit, and the arrival of another user message are not settlement evidence.

The rules were checked against Orca `bd9455b`, `src/shared/native-chat/transcript/native-chat-turn-fold.ts`: Orca uses settled host turn records and the last assistant prose, rather than a “no later tools” heuristic. Vade requires its own exact-session observations instead of importing Orca's journal or transport.

`conversation_rounds` stores bounded observed outcomes and work durations independently of Inbox/task results: up to 10,000 records overall and 200 per exact node/native conversation per read. These survive backend restarts and same-session resume. Existing public messages/tool previews stay in their native histories. Native Claude `turn_duration` records and matched Codex `task_started`/`task_complete` boundaries restore older timing from a bounded 4 MiB/200-boundary scan. Native elapsed time is distinguished from observed working intervals (which exclude waiting); native abort alone does not establish a user interruption. Missing historical timing remains unfolded. Source/branch resets still reset loaded history. Expansion preferences persist per browser and exact source/round, capped at 200 entries.

Conversation SSE publishes changed round observations even without a new public message. The current live work indicator remains separate from settled round disclosures. Earlier transcript rows and native tool details are retained, not rewritten or promoted into model/task success.

Claude model/effort changes may confirm from a fresh native `system/local_command` acknowledgement in addition to rendered terminal output. The reader captures a byte/inode and time fence immediately before Enter, then checks the exact session, workspace, command and argument. Historical, foreign, sidechain, replaced-file or failed acknowledgements cannot confirm. This accommodates wrapped/redrawn terminal output and delayed transcript flushes (up to 15 seconds) without replaying commands. ANSI formatting is removed only for metadata parsing; command rows remain private.

## Recorded images

Codex and Claude user turns, including image-only turns, can display recorded inline image attachments with lazy thumbnails and a shared modal preview. Image envelopes containing host paths are omitted from public text. The browser requests only an opaque image token bound to the exact project/node/source, row offset, image position and content digest. The backend revalidates public root-user eligibility and recorded bytes when serving the image, with restrictive MIME, CSP, no-sniff and same-origin headers. Rewritten rows cannot serve different images under an old token. It never fetches a remote URL or reads a browser-supplied host path. Foreign-session, sidechain, tool-result and internal images are excluded.

Limits are four images per message, 1 MiB per decoded image, 6 MiB of decoded images per page, and a 6 MiB record/read window for image-bearing transcript providers. PNG, JPEG, GIF and WebP require validated signatures; SVG and arbitrary HTML are not served. Missing/rejected bytes degrade to an unavailable preview. Other providers without verified recorded image shapes currently omit previews; this does not change attachment sending support.

Some Codex/Claude sends record only the staged image path as a user text line. When inline bytes are absent, Chat may resolve a direct UUID image file in its own backend attachment directory (up to the existing 5 MiB upload limit, within the same page budget). No other transcript host paths are read. Symlinks, hard links, traversal, nested/arbitrary names, private turns and unsupported signatures are refused. The preview route still binds source, native record offset, image index and byte digest, and revalidates the public turn and file on every request. Only a successfully projected attachment path is removed from the displayed prompt; missing/expired images retain their literal reference. The browser receives no host path.

## Permission choices

DeepSeek Harness exposes its mounted runtime permission roster through the native TUI channel. Codex uses its native `/permissions` menu, including Read Only, and confirms a change by reopening that menu and reading its `(current)` marker. Claude Code, CodeBuddy and Antigravity use native Shift+Tab with bounded, observed mode transitions rather than an assumed cycle order. Antigravity Auto means edits and safe commands, not Codex's approval reviewer. None of these four controls restarts the process or requires a saved transcript. An explicit Codex Full access selection may confirm its exact native “Enable full access?” warning once, including a previously open matching warning, before native readback. Other selections, changed warnings, setup and tool approvals are never automatically confirmed.

The compact colored picker sits beside Attach and uses the shared model-picker popover surface. Current values distinguish native evidence from launch policy. A shortcuts footer alone is never permission evidence; after a witnessed native mode, a fresh stable empty-prompt redraw can confirm a return to the default mode. Missing evidence, an unavailable native mode or a changed session fails without replay. Native launches retain their separate fixed permission preferences. Other providers without a verified live mechanism retain the confirmed restart path where supported.

Narrow chat panes use an accessible icon for model settings. Permission reads retry transient startup failures, refresh on opening/focus/visibility and cancel on source changes or disposal. Codex navigation confirms each individual arrow against fresh output. Its full-access warning is detected explicitly, including when the underlying composer appears empty: no second slash command is typed into a warning and no uncertain operation is retried. Claude's empty native composer does not require its optional shortcuts footer for either permission or model controls.

## Terminal image paste

Codex and Claude terminals read clipboard image bytes through the browser clipboard API or a captured paste event. Text-only clipboard contents retain normal terminal pasting. `POST /api/projects/:projectId/nodes/:nodeId/terminal-attachments` accepts only bounded validated image bytes; it cannot accept host paths, commands or a submit flag. Under the owned session's input lock, the backend stores generated private attachment files and stages native image paths as bracketed paste. It preserves existing single-line drafts and never sends Enter, creates a synthetic message or infers activity. Changed input/session, native setup/approval, unsupported providers and uncertain writes refuse without retry. Browser requests and paste listeners are disposed with the terminal pane.

Selecting a preset submits the fixed native `/permission` control under the same exact-session input lock as model changes. The terminal must be idle with an empty composer. The result is confirmed only by the channel's new permission selection. Provider risk confirmations, setup and approvals remain in Terminal; they are never automatically accepted. Unconfirmed changes remain errors and are not replayed. Closing Chat disposes its requests and focus listener.

## Rewind

Codex and Claude now expose **Rewind to here** for eligible exact native user anchors. Codex requires paginated native history, forks immediately before the target turn and verifies the retained boundary. Claude uses the official SDK's storage-only `forkSession` API with the selected message's native parent UUID; its custom store bounds the complete input to 16 MiB/20,000 rows, creates only a fresh UUID file and keeps the source unchanged. No SDK query or model request is made. Both keep disk changes and return text to the composer without sending it; image-bearing targets remain excluded. A read-only smoke test of installed Codex confirmed exact thread binding, paginated history and native user-item IDs.

Antigravity and CodeBuddy expose a rewind action beside each public user message. It switches to the existing Terminal view and enters the fixed native `/rewind` command once in an empty idle owned prompt. The user selects the actual target and file scope there; the clicked message is not automatically selected. There is no embedded rewind modal, label matching, inferred success or automatic retry. Source/workspace and workflow guards still apply.

CodeBuddy's append-only transcript retains discarded descendants. The reader follows native `resend-fork-notice` parent pointers instead of showing all stored rows. A native branch change rotates the public source identity, resetting old cursors and loaded Chat history; tool/model/context reads also exclude abandoned descendants. Replay is bounded to 16 MiB/20,000 rows and reports partial coverage rather than guessing missing ancestors. Native logs are never rewritten by this observer.

DSH public text messages projected by the updated observer carry a verified native sequence boundary. Eligible messages show **Rewind to here** beside the copy/time controls. The shared confirmation dialog explains that disk changes are kept. Existing composer drafts, active agents, pending approvals, another checkout writer and active workflows block the action. Messages with non-text attachments do not offer text-only rewind.

The request contains only opaque message/source/revision identifiers. The backend resolves the boundary from its own exact-session projection, rejects stale history, rechecks terminal input and the launch token, and confirms the owned terminal has exited before taking its native writer lease. It then creates a native continuation cut immediately before that user message, preserving the original native session and disk files. The same Vade node opens the new native identity with a fresh launch token. The selected text returns to the composer only after native readiness is observed; it is never submitted automatically.

Rewind uses the installed native persistence API, including its validation and single-writer ownership. Prefixes are limited to 4,000 events and 16 MiB. Continuation intent/completion receipts are scoped to the generated native target ID; a later rewind cannot reuse an earlier copy's receipt. Partial or uncertain copies are not retried or overwritten automatically. Earlier observers without native boundaries and other terminal providers keep the control hidden. This implementation does not modify raw provider logs or restore files from Git.

## Native boundaries and outcomes

Chat renders a context-compaction divider only for explicit native records: Codex `compacted`, Claude `system/compact_boundary`, CodeBuddy summary/compacted records with a native `compactionId`, DSH successful `compaction/end` observations, and OpenCode v2 completed `compaction` messages. Antigravity completed `CHECKPOINT` records use the distinct **Context checkpoint** label because native checkpoints can be intent-only. Private summaries remain hidden; generic context clears and prose are not compaction evidence. Unverified v1 formats remain absent. Native confirmed interruption takes precedence over the partial-work label: for example, **Interrupted after 34s**. The existing clock still measures observed working intervals, not guessed total elapsed time; merely clicking Stop does not establish interruption. Group and individual tool chevrons follow their summaries.

Selected-node conversation streams also publish bounded `node-status` observations independently of public message growth. The pane uses the newest observed node for its stop button and work timer, and disposes obsolete/hidden streams. Claude's exact synthetic interruption notice is omitted from public user messages. Native system/local-command effort acknowledgements update metadata and confirm controls, including quoted values and saved-default suffixes.

Codex preflight now maps a public draft to its recorded `item_completed/UserMessage` ID within the same `task_started` turn. Response-item IDs are not assumed to match native IDs. Ambiguous or truncated associations are refused. A separate app-server reader's `notLoaded` status is distinguished from active work in the owned terminal. Fork creation and cut verification finish before the source terminal closes; a refused fork leaves it open. An installed native smoke check successfully created and verified an empty fork before the oldest turn while preserving the source thread.

## Claude usage path

Conversations and workflow workers run the detected interactive Claude CLI in owned PTYs; Chat sends to that same process. Model catalogs use a `claude -p` control request for `list_models`, without a user inference prompt. Claude rewind uses a bundled, pinned development dependency's pure storage fork, not `query()`. Thus the reported SDK/headless five-hour metering discrepancy is not the application's chat transport. Provider accounting bugs may still affect the underlying CLI; Vade does not measure or promise a quota multiplier, add spoofed TUI headers or proxy credentials.
