# Source control

Successful explicit Git actions show the same bottom-right ActionNotice as Explorer copy/delete actions, with entry/exit motion, a dismiss control and automatic timeout. PR success retains its GitHub link. Both reuse Vade theme tokens and the shared confirmation lifecycle. View all file disclosures animate expansion/collapse through the shared Disclosure; closed editors are released after the transition, and quick reversals cancel disposal. Both respect reduced-motion preferences.

Source control is scoped to a registered project's discovered worktree, selected in a full-width picker above its branch. Changes and Staged changes collapse independently, with section actions outside each disclosure trigger. Rows show green additions and red deletions from their own working/index layer; bounded small untracked UTF-8 files use an empty baseline. Unknown/binary counts are omitted. The existing GitHub commits/PR/issues panel is separate and collapsed at the bottom by default. The upstream link always opens GitHub compare in a new tab, using `compare/<base>...<branch>?expand=1`, including `main...main`. It never looks up an existing PR or creates one. Local branch diff review remains in the options menu. No Git mutations occur on reads, polling, opening the sidebar or reviewing a diff.

The activity panel can be resized from its top separator with pointer/touch input or Up/Down keys; the height persists locally and clamps to available space. Graph commits expand into observed author/time and bounded changed-file rows, with statuses and the shared file icons. `GET /api/projects/:projectId/commit-files` binds a full SHA to the loaded project/worktree graph before reading file names. Root commits compare with an empty tree and merges use their first parent. Graph node dots stay at their own header row while rails stretch alongside expanded details. Per-node expand arrows do not use the widest graph row as their offset.

Both commit views read the same registered local checkout and locally known refs, including unpushed commits. The graph setting changes presentation only; scope, ordering, expansion, files and unread tracking stay identical. Fetch updates remote-tracking refs without moving the checked-out branch; Pull/fast-forward updates that branch and requires a clean checkout. Activity refresh and completed Source Control actions invalidate local history and GitHub activity immediately. Refresh never performs a network fetch or pull implicitly.

View all mounts editors only near the scroll viewport, retaining a focused editor until focus leaves. Offscreen editors and their Monaco models are disposed. A per-review LRU cache retains at most 12 diffs within an 8 MiB text budget for quick return visits; it is released when review closes.

Clicking a commit file reuses the normal Explorer file overlay in inline read-only historical mode through `GET /api/projects/:projectId/commit-diff`, bound to that exact graph SHA, scope and changed path. It reads commit/first-parent blobs rather than current working files, with explicit binary/size degradation. Historical views cannot save or poll working files; source and rendered Markdown remain read-only. Their cache is isolated by commit and graph scope. View all retains the multi-file review overlay. Review toolbar controls use labeled icons and pressed states. Unpublished branches offer Publish Branch as the primary action; staging remains available in the Changes header and per-file controls. PR/Issues tabs show one empty-state message while preserving actual read errors.

The sidebar separates staged changes from working-tree changes. Stage/unstage and discard controls appear on hover or keyboard focus, and remain visible on touch devices. File clicks reuse the Explorer file overlay in inline diff mode, retaining editing, Markdown, image controls and native shortcuts. Staged diffs show the exact index content read-only; switching to source edits the working file. Working diffs compare against the index. Untracked files compare with an empty original; deletions retain read-only review. Renames are addition/deletion pairs. Binary or oversized diffs have explicit placeholders. View all loads files automatically as their placeholders enter the scroll viewport, keeping large checkouts from constructing all editors immediately. Review supports side-by-side/inline, wrap and ignore-trim-whitespace options. Counts exclude unknown binary/untracked line totals.

Discard requires a confirmation bound to the selected file list and repository version. Tracked working files restore from the index; regular untracked files are permanently removed, without recursive directory deletion. The index is preserved. Stale confirmations, conflicts, symlinks and unsupported index modes refuse mutation. No discard runs as part of development verification.

Actions use `POST /api/projects/:projectId/source-control/action` and `SourceActionRequest`. Read endpoints `status`, `diff` and `compare` use discovered worktree IDs. Paths must be current changed files, are passed as literal pathspecs after `--`, and cannot traverse, resolve through symlinks or reach private runtime/Git metadata. Versions bind HEAD, branch, index entries, current status, file metadata and known remote refs. Every mutation rechecks that version under a per-checkout lock. Excluded paths block commits so unseen staged entries cannot accidentally enter a commit. Collection caps are explicit; truncated checkouts refuse mutation.

Commit includes only staged entries and requires a message. Commit & Push/Sync stop if the commit fails and do not retry uncertain writes. Remote actions target the existing origin, never a client-supplied URL. Publish sets the matching branch upstream. Pull/Fast-forward fetch and use `merge --ff-only`; Sync then performs a regular push. Divergence is an explicit Git error, never a silent merge or forced reset. Integration requires a clean checkout. Rebase uses a discovered selected ref and can leave conflicts for manual resolution; the app does not automatically abort or replay it. Force Push is always `--force-with-lease` with an explicit expected tracking SHA and requires confirmation.

GitHub PR creation requires a feature branch synchronized with its matching origin branch and a GitHub origin remote. The user reviews the title and description in a modal. A fixed `gh pr create` call receives a temporary body file and the discovered repository/base/head; native gh owns authentication. Failed or unconfirmed creation asks the user to inspect GitHub before retrying. No real PR is created as part of development verification.

The UI follows Orca's [source-control remote actions](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/right-sidebar/source-control-dropdown-remote-items.ts), adapted to existing Vade controls and standalone Git ownership. It does not depend on the Orca runtime. Tests remain skipped at the user's request; compilation/build checks do not establish remote authentication or live push/PR success.
