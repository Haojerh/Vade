# Session handoff

The agent overlay's **Hand Off** action starts a fresh detected, enabled coding agent in a selected discovered worktree. The current worktree is selected by default; another worktree can be chosen before starting. The original provider session remains unchanged. Focused handoff supplies recent public updates and a read-only context file; Full session transcript asks the new agent to read the complete exported public conversation first. Internal reasoning and tool output are never exported.

`server/runtime/sessionHandoff.ts` resolves history through `AdeConversations`, retaining exact-session identity and cursor fences. Exports are bounded to 1 MiB of message text, 1,000 messages, ten pages and a five-second scan window. Full mode refuses incomplete exports; focused mode explicitly labels bounded coverage. At most 200 export files are retained; reaching that limit refuses a new export. Files use generated names and backend-owned private paths.

`GET /api/projects/:projectId/nodes/:nodeId/handoff` returns the project's discovered destination worktrees. `POST` accepts only `HandoffSessionRequest` (`agentId`, `context`, `worktreeId`). The response identifies the newly created node and its `pending`, `submitted` or `uncertain` delivery state. The UI opens that node. A pending context can be explicitly submitted through `POST .../handoff-message` with an empty object after native setup is finished. Input is serialized and requires an observed empty, idle owned composer. Uncertain delivery is persisted before the first write and cannot be retried, including after a runtime restart. Changed source-session identity, checkout, or target launch token refuses pending delivery.

Active source agents, active peer writers and active workflows in the source or destination checkout prevent handoff. Handing off does not create an orchestration run, alter task outcomes, change provider settings or bypass native sign-in/trust. Handoff is standalone-only.

An uncertain-delivery notice is shown for the current overlay visit and is dismissed when that overlay closes. Its presentation state is bounded and browser-local in memory; the backend's persisted uncertain-delivery guard is preserved, so reopening never sends context again. Pending context retains its explicit send action.

DSH folds large native pastes into a chip at six lines or 600 characters. The send witness accepts its exact line and UTF-16 character counts plus the first-line preview when shown, inside the owned composer after a locked paste into an empty prompt. It submits one Enter and requires fresh native turn evidence. Mismatched or historical chips receive no Enter; uncertain delivery is never retried automatically.

Reference: Orca's [continuation dialog](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/agent-session-continuation/AgentSessionContinuationDialog.tsx), [prompt construction](https://github.com/stablyai/orca/blob/main/src/renderer/src/lib/agent-session-continuation.ts), and [readiness-aware launch](https://github.com/stablyai/orca/blob/main/src/renderer/src/lib/launch-agent-session-continuation.ts). Vade uses its existing shared UI and owned session API with public transcript exports rather than terminal captures or an Orca runtime dependency.
